### このプロジェクトの要点

- 本番: **PHP 7.2 / Laravel 5.8**（`acry-ya.com` / `admin.acry-ya.com`）
- 移行先: **PHP 8.5 / Laravel 13**（`acry-ya.com85` / `admin.acry-ya.com85`）
- 58系は**比較用に変更しない**。作業は85系だけ行う。
- カートシステム（Perl/CGI）は対象外。
- アップグレードは **5.8 → 6 → 7 → … → 13** と1メジャーずつ進める。

> **重要**: 現時点の85フォルダは「Laravel 5.8 のコピーを PHP 7.2 で動かしている Phase 0 の状態」です。
> まだ Laravel 13 / PHP 8.5 ではありません。いきなり8.5にすると動きません（後述）。

## 1. 受け取るもの（Git管理外）

以下は `.gitignore` 対象のため、リポジトリを clone しただけでは揃いません。
**管理者から別途受け取ってください。**

- [ ] `acry-ya.com/.env`
- [ ] `admin.acry-ya.com/.env`
- [ ] 必要に応じて `acry-ya.com85/.env` / `admin.acry-ya.com85/.env`

`.env` には `APP_KEY` が含まれます。**値は変更しないでください**（暗号化データの互換性が失われます）。
フロントと管理で `APP_KEY` は別物です。それぞれ対応する `.env` を使ってください。

85用は、受け取った58の `.env` をそのままコピーすればOKです。

```bash
cp acry-ya.com/.env acry-ya.com85/.env
cp admin.acry-ya.com/.env admin.acry-ya.com85/.env
```

`.env-dev` / `.env-stg` / `.env-prod` は本番系の認証情報を含むため、共有・コミットしないでください。

## 3. 初回セットアップ

### 3-1. 最短ルート（`acry-ya.com85` / `admin.acry-ya.com85` が既にある場合）

```bash
cd "/Volumes/Untitled 1/site/acry-ya2026/acry-ya-docker"

# Compose 用の環境変数
cp env.example .env

# 58系イメージのビルド
docker compose build front58 admin58

# MySQL / Mailpit 起動（初回は dump2026.sql の投入で1〜2分）
docker compose up -d mysql mailpit
docker compose ps          # mysql が healthy になるまで待つ

# 58系（現行）起動
docker compose up -d front58 admin58

# 85系（移行作業用）起動
docker compose --profile v85 up -d front85 admin85
```

### 3-2. 85フォルダが無い場合

`ai-document/docker.md` §9.2 の手順で複製します。
**rsync の除外パターンは必ず先頭に `/` を付けてください。**

```bash
cd "/Volumes/Untitled 1/site/acry-ya2026"

rsync -a \
  --exclude '/vendor' \
  --exclude '/node_modules' \
  --exclude '/storage/logs/*' \
  acry-ya.com/ acry-ya.com85/

rsync -a \
  --exclude '/vendor' \
  --exclude '/node_modules' \
  --exclude '/storage/app/public/img_storage/*' \
  admin.acry-ya.com/ admin.acry-ya.com85/

# 5.8時代のキャッシュを持ち込まない
rm -f acry-ya.com85/bootstrap/cache/*.php admin.acry-ya.com85/bootstrap/cache/*.php
find acry-ya.com85/storage/framework/views -type f -delete 2>/dev/null || true
find admin.acry-ya.com85/storage/framework/views -type f -delete 2>/dev/null || true
```

> `--exclude 'vendor'` と書くと `resources/views/vendor` まで除外され、
> 商品一覧が「View [vendor.pagination.default] not found」で500になります。必ず `/vendor`。

### 3-3. vendor のインストール

`vendor/` はGit管理外なので、clone直後は存在しません。初回のみ実行します。

```bash
cd "/Volumes/Untitled 1/site/acry-ya2026/acry-ya-docker"

# 58系（vendor が無い場合のみ）
docker compose exec -T front58 composer install --no-scripts --no-interaction --prefer-dist
docker compose exec -T admin58 composer install --no-scripts --no-interaction --prefer-dist

# 85系
# Laravel 5.8 は Composer 2 の installed.json 形式に非対応のため --no-scripts
docker compose exec -T front85 composer install --no-scripts --no-interaction --prefer-dist
docker compose exec -T admin85 composer install --no-scripts --no-interaction --prefer-dist

# 58側で生成済みのパッケージマニフェストを複製
cp ../acry-ya.com/bootstrap/cache/packages.php ../acry-ya.com85/bootstrap/cache/packages.php
cp ../admin.acry-ya.com/bootstrap/cache/packages.php ../admin.acry-ya.com85/bootstrap/cache/packages.php

# 権限
docker compose exec -T front85 chown -R www-data:www-data storage bootstrap/cache
docker compose exec -T admin85 chown -R www-data:www-data storage bootstrap/cache
```

Laravel 6.20 以降は Composer 2 に対応するため、Phase 1 完了後は `--no-scripts` が不要になります。

## 6. ハマりどころ（必読）

### 6-1. 85をPHP 8.5にしない

85フォルダはまだ Laravel 5.8 です。PHP 8.5 では動作しません。
PHPバージョンは `acry-ya-docker/.env` の `PHP85_VERSION` で管理し、フェーズに合わせて上げます。

```env
# Phase 0〜1
PHP85_VERSION=7.2.34
PHP85_COMPOSER_IMAGE=composer:2.2
```

| フェーズ | Laravel | `PHP85_VERSION` |
|---|---|---|
| 0〜1 | 5.8 / 6.x | `7.2.34` |
| 2〜3 | 7.x / 8.x | `7.4.33` |
| 4 | 9.x | `8.1.31` |
| 5 | 10.x | `8.2.29` |
| 6〜7 | 11.x / 12.x | `8.3.26` |
| 8〜9 | 13.x | `8.5.0` |

変更時:

```bash
cd acry-ya-docker
# .env を編集後
docker compose --profile v85 build --no-cache front85 admin85
docker compose --profile v85 up -d front85 admin85
```

### 6-2. `config:cache` は実行しない

設定をキャッシュすると `environment:` の変更が反映されなくなります。
この構成では `php artisan config:cache` を実行しないでください。

### 6-3. 以下も実行しない

| コマンド | 理由 |
|---|---|
| `php artisan key:generate` | 既存 `APP_KEY` を維持するため |
| `php artisan storage:link` | 画像は compose の bind mount で共有済み |
| `php artisan migrate` | DBはダンプ投入済み。マイグレーション履歴と不整合になるため |

### 6-4. DBユーザーの認証方式

Phase 0〜3 は PHP 7.x で動かすため、`acryya85` は `mysql_native_password` である必要があります。
新規DBボリュームでは `mysql/init/00-users.sh` が自動設定します。
既存ボリュームで `SQLSTATE[HY000] [2054]` が出た場合のみ、以下を実行します。

```sql
ALTER USER 'acryya85'@'%' IDENTIFIED WITH mysql_native_password BY 'acryya85';
FLUSH PRIVILEGES;
```

### 6-5. ログが巨大

`acry-ya.com/storage/logs` は過去に5GB超になっています。
コピー・バックアップ時は必ず除外してください。調査後は不要なログを退避・削除します。

### 6-6. 85の500エラー

85系は `APP_DEBUG=true` です。画面にWhoopsのスタックトレースが出ます。
コンテナログとアプリログを確認してください。

```bash
docker compose logs -f front85
tail -100 "/Volumes/Untitled 1/site/acry-ya2026/acry-ya.com85/storage/logs/laravel-$(date +%F).log"
```

## 7. Phase 0 の残タスク（最初の作業）

環境が起動したら、アップグレード前に「壊れたことが分かる状態」を作ります。

- [ ] `git init` の前に、各アプリの `.gitignore` へ `.env-*` を追記する
  - `.env-dev` / `.env-stg` / `.env-prod` に本番の認証情報が入っているため
  - 既存の `.gitignore` は `.env` のみ対象で、これらは除外されていない

  ```bash
  for d in acry-ya.com admin.acry-ya.com acry-ya.com85 admin.acry-ya.com85; do
    printf '.env-*\n' >> "$d/.gitignore"
  done
  ```

- [ ] `acry-ya.com` で `git init` → `git add .` → `git commit` → `git tag baseline-5.8`
- [ ] `admin.acry-ya.com` でも同様に `git init` + `baseline-5.8` タグ
- [ ] 作業対象の `acry-ya.com85` / `admin.acry-ya.com85` でも `git init` し、`phase-0-baseline` タグを付ける
- [ ] `git status` に `.env` / `.env-*` / `vendor/` / `storage/logs/` が出ていないことを確認
- [ ] DBをバックアップ

  ```bash
  cd acry-ya-docker
  docker compose exec -T mysql sh -c \
    'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction acryya_system' \
    > ../ai-document/backup-acryya_system-$(date +%Y%m%d).sql
  docker compose exec -T mysql sh -c \
    'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction acryya_system85' \
    > ../ai-document/backup-acryya_system85-$(date +%Y%m%d).sql
  ```

- [ ] 既存テストを実行し、成功/失敗/スキップを記録
- [ ] 主要URLのステータスコード一覧とスクリーンショットを保存
- [ ] 管理画面のログイン〜商品編集〜画像アップロードを一通り確認

Phase 1 以降の詳細は `ai-document/laravel-upgrade.md` を参照してください。
**各フェーズ開始前に Git タグとDBバックアップを取る**のがルールです。

## 8. よく使うコマンド

```bash
cd "/Volumes/Untitled 1/site/acry-ya2026/acry-ya-docker"

docker compose ps                          # 状態
docker compose logs -f front85             # ログ
docker compose exec front85 bash           # シェル
docker compose exec front85 php artisan route:list
docker compose exec front85 composer install --no-scripts --no-interaction
docker compose exec mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" acryya_system85'

# 停止（データは残る）
docker compose --profile v85 stop front85 admin85
docker compose stop

# 再起動
docker compose restart front85
```

> **注意**: `docker compose down -v` はDBボリューム（`db-data/`）を削除します。
> ダンプから再作成はできますが、作業中のデータは消えます。通常は使わないでください。

## 9. 困ったときの確認順

1. `docker compose ps` で対象コンテナが `Up` か
2. `docker compose logs --tail=100 <service>` にエラーが出ていないか
3. `storage/logs/laravel-YYYY-MM-DD.log` を確認
4. `curl -s -o /dev/null -w '%{http_code}' http://localhost:8000/` でステータス確認
5. DB接続エラーなら、コンテナ内で接続先を確認

   ```bash
   docker compose exec -T front85 php -r \
     'require "vendor/autoload.php"; $app=require "bootstrap/app.php"; $app->make(Illuminate\Contracts\Console\Kernel::class)->bootstrap(); print_r(Illuminate\Support\Facades\DB::select("select @@hostname h, database() d, user() u"));'
   ```
6. それでも分からなければ、変更したファイルと実行したコマンドを添えて相談

## 10. 作業時の心得

- **58系は変更しない**（比較の基準）。変更するのは85系のみ。
- **1メジャーずつ上げる**。複数バージョンを一度に上げない。
- **フェーズごとにコミット・タグ・DBバックアップ**。
- 判断に迷う変更は `ai-document/` に記録を残す。
- 本番の認証情報・`.env`・ダンプを外部に共有しない。
